# Expo example app

The toolkit's test bed and demo: an Expo SDK 57 app with a dev client and Expo Router, a Vite web app in `web/`, and a dependency-free local API over a SQLite database per lane. `README.md` has the build, launch, flow and test commands, the API's requests, the bundle id, the scheme, the test account and the testIDs. The run skill in `.agents/skills/run/` (linked from `.claude/skills/run` for Claude Code) is how to bring it up and prove a change.

## Rules

- This is its own pnpm project with its own lockfile. Run every command from `examples/expo-app`, never from the repository root, and keep it out of the root package.
- Expo changes between SDKs. Before touching an Expo or React Native API, read the docs for SDK 57 (`https://docs.expo.dev/versions/v57.0.0/`, or `https://docs.expo.dev/llms.txt` for the index) rather than relying on memory.
- Add packages with the version `node -p 'require("expo/bundledNativeModules.json")["<package>"]'` gives, through `pnpm add`. `expo install` spawns a different pnpm on this Mac and fails with `ERR_PNPM_UNEXPECTED_STORE`. `react-dom` stays at the exact version of `react`, which React Native pins.
- `ios/` and `android/` are generated by prebuild and never committed. Configure native behaviour in `app.json`.
- The web app reaches the API only through its own `/api` path, which the Vite dev server proxies to `API_URL`. An absolute API address would put the session cookie on another origin.
- A schema change is a new entry at the end of `migrations` in `api/database.mjs`. Never edit one that has shipped: every lane's database has already applied it, and the API migrates an existing database when it starts.
- Every element a flow, a web test or the driver touches gets a `testID` (a `data-testid` on the web), and the README's testID table lists it.
- Web tests find elements by role and label, and run both against a lane (`agentlane exec -- npx playwright test`, whose database keeps every earlier run's rows) and on their own. Give each row a test writes a unique name, and never assume an empty table. A test that signs out signs in through the form first: signing out the saved login would sign the lane's browser out too.
- `@playwright/test` stays at the toolkit's Playwright version (`agentlane doctor` names it), or the tests can't find a browser under `exec`.
- Nothing names a real product, person or company. The only account is the seeded test login; no secrets or remote services.
- Never serve Metro on 8081 or 8082.

## Checks

```bash
pnpm run typecheck
pnpm run lint
pnpm run test:web
```

and the Maestro flows in `.maestro/` against a running build when you change a screen.
